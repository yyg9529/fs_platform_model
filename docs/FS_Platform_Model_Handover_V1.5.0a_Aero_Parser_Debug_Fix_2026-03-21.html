FS Platform Model 交接文档（V1.5.0a｜Aero Parser / Debug Fix）

本文件记录 V1.5.0a 的一次阻塞级基础修复。重点不是继续扩展轮胎代理层，而是先修复更前置的气动插值层 parser/debug 阻塞，使两个 V1.5 demo 能真正穿过 aero map 并进入 tire layer。

问题定位

  • 阻塞文件：aero/interp_aero_map.m
  • 原始报错：非法使用保留关键字 end
  • 真实调用链：demo_tire_table_* -> run_case -> solve_equilibrium -> residual_equilibrium -> calc_external_loads -> calc_aero_state -> interp_aero_map
  • 根因不是 tire layer 本体，而是更前置的 aero parser/兼容性问题。

本次核心修复

  • 修复 interp_aero_map.m 首行异常字符污染，消除 ifunction 风险。
  • 将 interp_aero_map.m 收口为单主函数文件，移除尾部 local helper function。
  • 继续保留 4D aero map 插值，不用常数占位绕过。
  • 继续保留 query clamp、linear -> nearest fallback、透明 flag 输出。
  • pitchMomentTable 继续作为可选项，缺失时返回 0.0。

保持不变的边界

  • 不重建项目，不改主目录结构。
  • 不改 run_case -> validate -> preprocess -> solve -> postprocess 主链。
  • 不把 V1.5 tire layer 塞回主平衡方程。
  • 不删除 aero map、beta、phi 或透明 warning/flag 语义。

当前结论： 本轮修复点明确位于 aero map 解析层，而不是 tire layer 本体。`V1.5` 轮胎代理层的工程边界保持不变。

验证结果

  • 新增并通过 4 项 aero 插值层直接测试。
  • 既有 test_aero_map_flags 继续通过。
  • demo_tire_table_pure_lateral 已通过 aero 原阻塞点并进入 tire layer。
  • demo_tire_table_brake_in_turn 已通过 aero 原阻塞点并进入 tire layer。
  • 两个 demo 当前可能出现 evaluate_tire_table_model:OutOfRange warning，但这属于非阻塞轮胎表覆盖问题。

运行时目录说明

  • 本轮排障过程中曾临时生成 .matlab_env、.matlab_prefs、.tmp 等运行时目录。
  • 这些目录不是项目源码，不应被打包进正式 zip。
  • 后续版本打包时应显式排除这类运行时产物，否则会异常放大包体积。

下一线程建议

  • 继续保持 interp_aero_map.m 的单主函数写法，不要重新引入尾部 local helper。
  • 若继续做 V1.5.x，优先收口示例 tire table 的 out-of-range warning，而不是重新改 aero parser。
  • 若未来继续修改气动插值层，应继续保留 clamp/fallback/flag 的透明语义。
